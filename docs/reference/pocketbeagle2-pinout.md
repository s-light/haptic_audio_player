# PocketBeagle 2 – P1/P2 header pin table

Source: <https://docs.beagleboard.org/boards/pocketbeagle-2/04-expansion.html>
(fetched 2026-10-04, tables converted to one row per pin).
Pad offset = register address − `0x000F4000` (the value used in `AM62X_IOPAD(offset, flags, mode)` in device-tree overlays).

> [!WARNING]
> All header signals are **3.3 V**. Never connect 5 V logic. Do not drive any pin while the board is unpowered.
> Pins with an `A` suffix (e.g. `P2.03A`) share the same physical header pin with the un-suffixed one –
> *two SoC balls are shorted together*, only one of them may be actively used at a time.

Modes listed as `~` (unused) are omitted. GPIO column = `GPIOx_y` → `gpiochip` of controller `x`, line `y`.

| Pin | Signal |
| :-- | :----- |

| P2.16 | BAT.TEMP - BAT_TS |
| P2.23 | VDD_3V3 |

Note: `P1.24` is the 5 V `VOUT` pin, `P2.13` is `VSYS` (system rail), `P2.12` is the power-button input (pull to GND), `P1.17/P1.18` are the analog reference pins.

Note: pad offsets of `MCU_*`/`P1.26A`-style (MCU-domain) balls are relative to a different base (`0x04084000`
region) and are *not* usable with `main_pmx0`; we do not use any of them.
